# 第 19 版：ZeroTier 默认网关与恢复防火墙复用

基于第 18 版。源码及隔离回归已检查，完整固件仍需云端构建和实机验证；源码 ZIP 不能刷入路由器。

## 本版修改

- 固定开启所有从 zt* 接口进入的 ZeroTier IPv4 客户端借本机上网；删除页面开关、对应说明及客户端网段输入。
- 忽略旧 zt_gateway=0 和 zt_sources；应用时清除网关转发及 DNS 放行规则的 src_ip 限制。仍需在 ZeroTier Central 配置经本机的默认路由，并在客户端允许默认路由及配置 DNS。
- 为恢复 restart 增加 RAM 中的成功安装快照。期望规则、实际 nft 表、策略路由全部与上次成功安装一致时，跳过首次 nft 校验与重建，减少旧 Xray 运行期间的额外开销。
- 任一状态变化、读取失败或快照缺失都完整安装；安装失败使快照失效。普通防火墙调用仍完整安装。保留原故障阻断。
- 更新页面、旧配置兼容及防火墙复用回归测试，加入云端验证流程。

## 保留功能

保留第 18 版四种模式、DNS 候选复用、按 dnsmasq 主进程刷新缓存、启动守护宽限、最近 10 条节点日志和代理探测记录、备用节点遍历及恢复耗时记录。mangozt 入站 ACCEPT、出站 ACCEPT、转发 REJECT，IPv4 动态伪装开启、源/目标网段留空；管理位置仍在防火墙页面。

## 验证与未解决问题

- 页面和订阅 Node 测试通过；Windows Python 单元测试 10 项通过、20 项因需 Linux 环境跳过，交由云端执行。
- 路由器 /tmp 隔离环境已通过 Lua 策略与配置测试、新旧防火墙复用回归；未替换在线服务，尚未实机验证第 19 版。
- 首次安装及规则变化仍会完整重建防火墙，不能保证彻底消除 OOM。
- 第 18 版曾出现 Xray 预检约 192 秒，原因仍未定位；本版不取消预检、不声称修复此问题。
- 没有新增 IPv6 透明代理、Swap、预检缓存或完整事务回滚；所有候选失败时仍可能重启当前节点。
- 保留第 18 版源码归档作为回退基线；不合入此前未通过的进程交接实验。

## 日志

- `/var/etc/mango/probe-history`：最近 10 轮代理探测。
- `/var/etc/mango/node-history`：最近 10 条节点切换记录。
- `/var/etc/mango/apply-timing`：最近一次启动/应用阶段耗时。
- `/var/etc/mango/recovery-timing` 与 `.previous`：最近两次自动恢复阶段。

## 构建与使用

设备：GL-MT300N-V2。使用固定 OpenWrt 25.12.5 源码，Xray 26.3.27；版本与规则摘要见 scripts 中的构建脚本。

Actions 工作流先验证源码，再编译、检查容量与 MIPS Xray 配置；成功产物包含 sysupgrade.bin、SHA256SUMS 和本说明。固件默认直连、自动切换关闭，不包含个人节点、订阅凭据或 ZeroTier 身份。

刷机前备份当前配置；保留旧配置刷入时，旧的用户配置可能覆盖本版默认防火墙设置。仅刷 sysupgrade.bin，不刷源码 ZIP。
